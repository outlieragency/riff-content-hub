# Earth Rati — Facebook Content Style Guide

คู่มือเขียน Facebook content ภาษาไทยในสไตล์ของ **Earth Rati**
ไฟล์นี้โฟกัสที่ **โครงสร้าง + voice + writing rhythm** ส่วน CTA ตอนท้ายผู้เขียนใส่เอง

---

## หลักการสำคัญ (อ่านก่อนเริ่ม)

โพสต์ของ Earth Rati เป็นการผสมระหว่าง:
- **Educational depth** — เล่า case study/framework ละเอียด มี takeaway ชัด
- **Personal voice** — มี context ส่วนตัว ไม่ใช่ generic content
- **Practical bridge** — เชื่อม Western frameworks → Thai audience
- **Soft authority** — เป็น insight provider ไม่ใช่ guru

**3 จุดที่ทำให้โพสต์เป็น Earth Rati:**
1. เปิดด้วย hook ที่มีตัวเลข + ผลลัพธ์ + วิธีการ
2. มี personal context ใน intro (เจอเรื่องนี้จากไหน + ทำไมสนใจ)
3. ปิดด้วย signature: "หวังว่าโพสต์นี้จะมีประโยชน์กับทุกคนนะครับผม"

---

## Voice & Persona

### Self-reference
- ใช้ **"เอิร์ธ"** หรือ **"ผม"** สลับกันได้
- "เอิร์ธ" — ใช้เมื่อเล่าประสบการณ์ตรงของตัวเอง ("เอิร์ธเคยลองทำมาแล้ว...")
- "ผม" — ใช้เมื่ออธิบาย/วิเคราะห์ ("ผมว่าจุดนี้สำคัญมาก...")
- ห้ามใช้ "แอด" หรือ "เรา"

### โทนการพูด
- เหมือนเพื่อนสนิทที่อ่าน/ฟัง insight ดี ๆ มาแล้วอยากเล่าให้ฟัง
- ไม่ได้สอน แต่กำลัง share สิ่งที่ตัวเองเรียนรู้มา
- มี personal aside ได้: "ตอนแรกเอิร์ธก็งงเหมือนกัน 5555"

### คำลงท้าย
- `ค้าบ`, `ค้าบบ`, `ค้าบบบ` — ใช้บ่อยที่สุด
- `ครับ`, `ครับผม` — ใช้เวลาเป็นทางการขึ้นนิด หรือปิดประโยค
- `น้าา`, `นะครับ` — ใช้เชิญชวน
- หัวเราะ: `5555`, `55555`, `555555` (ห้ามใช้ ฮ่าาา ฮ๋าาา)

### Code-switching ไทย-อังกฤษ
- คำศัพท์เฉพาะทาง เก็บอังกฤษ: Deep Work, Product Market Fit, Funnel, Offer
- ใส่คำแปลในวงเล็บถ้าศัพท์ใหม่/ยาก: "Resting Heart Rate (หัวใจเต้นตอนพัก)"
- ห้ามแปลทุกคำ ทำให้อ่านเหมือนหนังสือเรียน

## โครงสร้างโพสต์

```
[1] HOOK              — บรรทัดเดียว: ตัวเลข + ผลลัพธ์ + วิธีการ
[2] (Subhook ในวงเล็บ) — optional, ขยายความ hook
.
[3] INTRO             — personal context + แหล่งที่มา + promise
#อ่านจบปุ๊ปเก่งขึ้นปั๊ป
==========
[4] MAIN POINTS       — [1] [2] [3] [4] ใช้สัญลักษณ์ครอบ
==========
[5] OFFER POINT       — (optional) point สุดท้ายที่เชื่อมเข้า product/service
==========
[6] #สรุ๊ปสรุป     — bullet 5-6 ข้อ keyword EN + อธิบาย TH
==========
[7] #ความเห็นฉบับเอิร์ธ — มุมมองส่วนตัว + CTA (ผู้เขียนใส่เอง)
.
หวังว่าโพสต์นี้จะมีประโยชน์กับทุกคนนะครับผม
```

---

## ตัวคั่น (Separator)

- ใช้ `==========` (เท่ากับ 10 ตัว) คั่น section ใหญ่
- ใช้ `.` บรรทัดเดียว คั่นย่อหน้าภายใน section
- **ห้าม** เว้นบรรทัดว่าง 2 บรรทัด ใช้ `.` เสมอ
- **ห้าม** ใช้ markdown header (`#`, `##`) ภายในเนื้อหา

---

## Hook (บรรทัดแรก)

**Pattern หลัก:** `[ตัวเลขใหญ่] + [ผลลัพธ์ที่น่าทึ่ง] + [วิธีการ/เครื่องมือ]`

**ตัวอย่าง:**
- "วัยรุ่น Gen Z เงินแสนต่อเดือน เด็กอายุ 14 สร้างแอปดูแลสุขภาพในรูปแบบเกม ด้วยการใช้ Claude Code และขั้นตอนเหล่านี้"
- "สร้างรายได้หลักล้านต่อเดือนด้วยตัวคนเดียว จากการสร้าง app กว่า 35 ตัวด้วย AI สรุปออกมาเป็น framework ที่สามารถทำตามได้"

**Pattern alternative — Authority hook:**
- "ความลับของการนอนที่คนเข้าใจผิด จากคุณหมอที่รักษาคนไข้ด้านการนอนมากว่า 26 ปี"

**Pattern alternative — Curiosity hook:**
- "คนที่นอนดีที่สุดในโลก ทำอะไรต่างจากเรา"

**Subhook (optional):**
ถ้า hook หลักดูแห้ง เพิ่ม subhook ในวงเล็บบรรทัดถัดไป
```
วิธีเขียน Journal (บันทึกตัวเอง) แบบนักปรัชญาทำ
(การเขียน Journal คือความลับของคนเก่ง)
```

**กฎ Hook:**
- ความยาว 1 บรรทัด อ่านเป็นประโยคเดียว
- ต้องมีตัวเลข specific (ห้ามเขียน "หลายล้าน" ให้เขียน "500,000 บาท")
- ต้องระบุ "วิธีการ/เครื่องมือ" เพื่อ tease

## Intro (เปิดเรื่อง)

โครงสร้าง 3 ย่อหน้า แยกด้วย `.`:

### ย่อหน้า 1 — Source + Personal Context

**ต้องมี:**
- แหล่งที่มา (podcast/รายการ/หนังสือ/บทสัมภาษณ์/งาน event)
- ระบุชื่อคนที่อ้างอิง
- (Optional) เล่าว่าเอิร์ธเจอเรื่องนี้ตอนไหน

**ตัวอย่าง:**
```
ใน Podcast ของ Logan Paul เขานั่งคุยกับ Bryan Johnson
(คนที่เขาเคลมว่าอายุร่างกายเขาเดินช้าที่สุดในโลก)
ถามไปหลายเรื่องเลย จนเขาคุยกันจนมาถึงเรื่องการนอน
```

```
จากเด็กวัย 14 ปี ที่เริ่มสร้างเกมใน Roblox ตั้งแต่ 9 ขวบ
สู่เจ้าของแอป Locked ที่สร้างรายได้ 500,000 บาทต่อเดือน
ภายในเวลาเพียงไม่กี่เดือน นี่คือบทสัมภาษณ์จากรายการ Starter Story
```

### ย่อหน้า 2 — Hook quote หรือ Insight เด็ด

**ตัวอย่าง:**
```
Bryan Johnson บอกว่า "การนอนคือ ยาที่มีประสิทธิภาพมากที่สุดในโลกนี้"
เขาบอกว่าหลักๆเราต้องเข้าใจ 5 ข้อนี้เลย
```

### ย่อหน้า 3 — Promise + Hashtag

**ต้องมี:**
- บอกว่าเอิร์ธ/ผมจะพาดูอะไร
- ระบุ outcome ที่คนอ่านจะได้
- ปิดด้วย `#อ่านจบปุ๊ปเก่งขึ้นปั๊ป`

**ตัวอย่าง:**
```
วันนี้เอิร์ธจะพามาดูทั้งแนวคิดและ framework ที่เขาใช้
สรุปมาจากกรณีศึกษาจริง ใครก็ทำตามได้ เริ่มจาก 0
ไม่ให้เป็นการเสียเวลา ไปลุยกันเลยครับ
#อ่านจบปุ๊ปเก่งขึ้นปั๊ป
```

**กฎ Intro:**
- ต้องมี personal context (เอิร์ธเจอจากไหน/สนใจเพราะอะไร)
- ต้องระบุแหล่งที่มาแบบเฉพาะเจาะจง
- ปิดด้วย `#อ่านจบปุ๊ปเก่งขึ้นปั๊ป` ทุกครั้ง
- เพิ่ม comment ในวงเล็บได้: "(ตอนฟังเอิร์ธก็งงเหมือนกัน 5555)"

## Main Points

### Format

```
[เลข] [หัวข้อภาษาไทย/ผสมอังกฤษ]
[ย่อหน้า 1: setup ปัญหา/บริบท + ระบุชื่อคน/บริษัท]
.
[ย่อหน้า 2: รายละเอียดวิธีการ + ตัวเลข specific]
.
[ย่อหน้า 3: ผลลัพธ์/ตัวอย่าง/quote เด็ด]
```

### กฎเขียนหัวข้อ

- ใช้ `[1]` `[2]` `[3]` ครอบเลข (ห้ามใช้ `1.` หรือ `1)`)
- ห้ามใช้ markdown bold (`**`)
- ผสมไทย-อังกฤษได้: "Tech Stack ปี 2026 และความเร็วในการพัฒนาแบบ Vibe Coding"
- ใส่ตัวเลข/keyword จับใจ: "อัตราความสำเร็จแค่ 5% ก็รวยได้"

### กฎเขียนเนื้อหา

- 3-5 ย่อหน้าต่อข้อ คั่นด้วย `.` บรรทัดเดียว
- **ใส่ตัวเลข specific** เสมอ (44 bpm, 26 ปี, 1,400 บาท)
- ใส่ตัวเลขเงิน THB + USD ถ้าเป็น case ต่างประเทศ: "1,400 บาท ($40)"
- บอกชื่อคน/บริษัท/แอปแบบเฉพาะเจาะจง
- ใส่ direct quote ได้ (ในเครื่องหมาย " "): `Bryan บอกว่า "การนอนคือ ยาที่มีประสิทธิภาพมากที่สุด"`
- ใส่ personal aside ได้: "ตอนฟังเอิร์ธจดมาไม่ค่อยทันเท่าไหร่ 55555"

### ตัวอย่างจริง (Earth Rati style)

```
[3] Tech Stack ปี 2026 ความเร็วคือ KPI เดียวที่สำคัญที่สุด
.
ในยุคที่ทุกคนตื่นเต้นกับระบบ AI Agent ที่ซับซ้อน
Marc กลับใช้ Setup ที่น่าเบื่อที่สุดเท่าที่เคยมีมา
เขาแค่ใช้หน้าต่างแชท AI เพียงหน้าต่างเดียวคู่กับ Code Editor
แล้วสั่งให้ AI ช่วยสร้างฟีเจอร์ใหม่ ๆ ออกมาทีละอย่างแล้วปล่อยใช้งานทันที
.
เขาพิสูจน์ความเร็วนี้ด้วยการปล่อยฟีเจอร์ไปกว่า 300 อย่าง
บน Marketplace ของเขาในเวลาเพียง 3 เดือน
และสร้างแอปใหม่ถึง 6 ตัวในปีนี้
.
ผมว่าจุดนี้สำคัญมาก เพราะมันสะท้อนว่า
ความสำเร็จของ Solo Entrepreneur ในยุค AI
ไม่ได้อยู่ที่ระบบสวยหรู แต่อยู่ที่ "ปล่อยของบ่อยแค่ไหน"
```

## Offer Point (Optional — เมื่อต้องการเชื่อมเข้า product/service)

ถ้าโพสต์นี้จะขายของ ใส่เป็น **point สุดท้ายของ main points** (เช่น `[5]` หรือ `[6]`)
ก่อนเข้าสู่ #สรุ๊ปสรุป

**โครงสร้าง:**
```
[เลข] [ชื่อ Product/Service ของผู้เขียน]
[ประโยคเชื่อม — สรุปว่าเรื่องที่เล่ามาเป็นแค่ "แนวคิดคร่าว ๆ"]
.
[Credibility — ผม/เอิร์ธทำมาจาก... ใช้เวลา... ลงทุน...]
.
[What's inside — สิ่งที่ลูกค้าจะได้]
[ผู้เขียนใส่ pitch ของตัวเองตรงนี้]
```

**หมายเหตุ:** Section นี้ผู้เขียนใส่เนื้อหาเอง ไฟล์นี้แค่บอกว่า "วางตรงไหน" และ "โครงประมาณไหน"

## #สรุ๊ปสรุป

**Format:** bullet 5-6 ข้อ ขึ้นด้วย `- [Keyword EN] [คำอธิบาย TH]`

**ตัวอย่าง:**
```
#สรุ๊ปสรุป
- Gamified Health เปลี่ยนแอปสุขภาพให้น่าสนใจด้วยระบบตัวละครและ XP
- Targeted Niche ค้นหา Influencer ที่ทำคอนเทนต์ "จดจ่อกับงาน"
- Arbitrage Marketing เน้นคุมต้นทุน CPM ให้ต่ำกว่ารายได้เสมอ
- Vibe Coding Speed ใช้ Claude Code และ Figma พัฒนาแอปจนเสร็จภายใน 1.5 เดือน
- Action over Education มองว่าประสบการณ์สำคัญกว่าระบบการศึกษา
```

**กฎ:**
- Keyword เป็นอังกฤษ + เป็น noun/concept (Gamified Health, The 5% Rule, Deep Work Priority)
- คำอธิบายเป็นภาษาไทย กระชับ 1 บรรทัด
- จำนวน 5-6 ข้อ ห้ามเกิน 7
- ห้ามใช้ emoji หรือ formatting อื่น

## #ความเห็นฉบับเอิร์ธ + CTA

**Pattern:**
1. เปิดด้วย hook/disclaimer — "ผมขอเสริมมุมมองหน่อย", "เอิร์ธว่าจุดนี้น่าคิด..."
2. แสดงมุมมองส่วนตัว — เห็นด้วย/เห็นต่าง/เพิ่มเติม
3. **CTA — ผู้เขียนใส่เอง** (เชิญซื้อสินค้า/บริการของตัวเอง)
4. ปิดด้วย signature line

**ตัวอย่างเปิด #ความเห็นฉบับเอิร์ธ:**
```
#ความเห็นฉบับเอิร์ธ
ผมว่า [ชื่อคน] คือตัวแทนของ Solo Entrepreneur ยุคใหม่
ที่เลิกหลงรักไอเดียตัวเอง แต่หันมาหลงรักกระบวนการผลิตแทน
.
ในปี 2026 ที่ AI ทำให้ใครก็สร้างของได้ ความแตกต่างเดียวที่เหลือคือ
ใครจะอึดและปล่อยของได้บ่อยกว่ากัน
.
[CTA — ผู้เขียนใส่เอง: เชิญซื้อสินค้า/บริการ]
```

**Signature ปิดท้าย (ห้ามขาด):**
```
หวังว่าโพสต์นี้จะมีประโยชน์กับทุกคนนะครับผม
```

## Universal Rules

### Typography & Formatting

- **ห้ามใช้ markdown** (`**bold**`, `# header`, `> quote`) ในเนื้อหาโพสต์
- **ห้ามใช้ตาราง markdown**
- ใช้ `.` บรรทัดเดียวคั่นย่อหน้าเสมอ ห้ามเว้นบรรทัดว่าง
- Bullet points ใช้ `-` (dash) เท่านั้น ห้ามใช้ `•` หรือ `*`

### ภาษา

- Code-switching ไทย-อังกฤษเป็นเรื่องปกติ และควรมี
- คำศัพท์เฉพาะทางเก็บภาษาอังกฤษ
- คำที่อาจไม่คุ้น ใส่คำแปลในวงเล็บ

### ข้อห้าม

- ❌ ห้ามใช้ "ครับ/ค่ะ" แบบทางการเกินไป (ใช้ `ค้าบ`, `ครับผม` แทน)
- ❌ ห้ามขึ้นย่อหน้าด้วยการเว้นบรรทัด ใช้ `.` แทนเสมอ
- ❌ ห้ามใช้ emoji เยอะ (มากสุด 1-2 ตัวต่อโพสต์ หรือไม่ใช้เลย)
- ❌ ห้ามใช้ "Conclusion:" หรือ "Summary:" แบบ formal
- ❌ ห้ามใช้ markdown header (`#`, `##`) ในเนื้อหา (ใช้ได้แค่ใน hashtag เช่น #สรุ๊ปสรุป)
- ❌ ห้ามใช้ "แอด" หรือ "เรา" — ใช้ "เอิร์ธ" หรือ "ผม" เท่านั้น
- ❌ ห้ามใช้ `1.` `2.` `3.` — ใช้ `[1]` `[2]` `[3]` เท่านั้น

### ข้อบังคับ

- ✅ ต้องมีตัวเลข specific อย่างน้อย 3 ตัวต่อโพสต์
- ✅ ต้องมีชื่อคน/บริษัท/แอปแบบเฉพาะเจาะจง (ห้าม "บริษัทนึง")
- ✅ ต้องมี case study หรือตัวอย่างจริง ห้าม generic
- ✅ ต้องมี `#อ่านจบปุ๊ปเก่งขึ้นปั๊ป` หลัง intro
- ✅ ต้องมี `#สรุ๊ปสรุป`
- ✅ ต้องปิดด้วย "หวังว่าโพสต์นี้จะมีประโยชน์กับทุกคนนะครับผม"

## Template — Skeleton พร้อมใช้

```
[HOOK บรรทัดเดียว: ตัวเลข + ผลลัพธ์ + วิธีการ]
([Subhook optional ในวงเล็บ])
.
```

## Notes สำหรับ Claude Code

เมื่อต้อง generate Facebook post ใหม่:

1. **ถามก่อนเริ่ม:**
   - Topic คืออะไร?
   - Source/case study ที่จะอ้างอิง? (podcast/หนังสือ/บทความ/case ของลูกค้า)
   - มี Offer Point ไหม? ถ้ามี product/service อะไร? (เอิร์ธจะใส่ pitch เอง — ไม่ต้องเขียนแทน)
   - มี CTA ตอนท้ายไหม? ผู้เขียนจะใส่เอง — Claude Code แค่เว้น slot ไว้

2. **ใช้ Template skeleton** เป็นโครงเสมอ อย่าด้นสด

3. **ห้ามใส่ markdown formatting** ใน final output — ต้องเป็น plain text ที่ paste ลง Facebook ได้ทันที

4. **ตัวเลขต้อง specific** — ห้าม "หลายล้าน" "หลายสิบ" ให้ใส่ตัวเลขจริง

5. **Voice consistency check:**
   - ใช้ "เอิร์ธ" หรือ "ผม" สลับกันได้ แต่ห้ามใช้ "แอด" "เรา"
   - หัวเราะใช้ `5555` `55555` (ไม่ใช่ ฮ่าาา)
   - คำลงท้ายใช้ `ค้าบ` `ครับผม` `น้าา`

6. **Slot ที่ผู้เขียนจะใส่เอง** — เว้นว่างไว้พร้อม comment:
   - Offer Point (ถ้ามี): `[ผู้เขียนใส่ pitch product/service ของตัวเองตรงนี้]`
   - CTA ใน #ความเห็นฉบับเอิร์ธ: `[ผู้เขียนใส่ CTA ของตัวเองตรงนี้]`

7. **Checklist ก่อนส่ง:**
   - [ ] Hook มีตัวเลข + ผลลัพธ์ + วิธีการ
   - [ ] Intro มี personal context + แหล่งที่มา
   - [ ] มี `#อ่านจบปุ๊ปเก่งขึ้นปั๊ป` หลัง intro
   - [ ] Main points ใช้ `[1] [2] [3]` ไม่ใช่ `1. 2. 3.`
   - [ ] ใช้ `==========` คั่น section
   - [ ] ใช้ `.` คั่นย่อหน้า ไม่ใช่บรรทัดว่าง
   - [ ] มี #สรุ๊ปสรุป (5-6 bullets, keyword EN + อธิบาย TH)
   - [ ] มี #ความเห็นฉบับเอิร์ธ + slot สำหรับ CTA
   - [ ] ปิดด้วย "หวังว่าโพสต์นี้จะมีประโยชน์กับทุกคนนะครับผม"
   - [ ] ไม่มี markdown formatting (`**`, `#`, `>`)
